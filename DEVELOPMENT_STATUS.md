# Astra VPN — статус разработки

## Реализовано в текущей ветке

- Android-клиент на Kotlin, minSdk 24 / targetSdk 35.
- Интеграция Android libbox (sing-box 1.14.3) и VPN-службы на базе `VpnService`.
- Создание TUN-интерфейса через Android `VpnService.Builder`, маршруты IPv4/IPv6 и DNS.
- Обработка смены сети через `ConnectivityManager.NetworkCallback`.
- Импорт VLESS, Hysteria2 и TUIC URI, загрузка HTTPS-подписок с ограничением размера, проверкой перенаправлений и конфигурации.
- Хранение профилей с шифрованием AES/GCM через Android Keystore.
- Настройка маршрутизации приложений: выбранные приложения через VPN или исключение выбранных приложений.
- Сортировка серверов по задержке; серверы без результата/с ошибкой располагаются в конце списка.
- Проверка интернет-доступа именно через VPN-сеть. Captive portal и отсутствие VPN-транспорта не считаются защищённым соединением.
- Отдельное предупреждение в интерфейсе, если VPN формально подключён, но интернет через туннель недоступен.
- TCP-проверка доступности VLESS endpoint: DNS отдельно, пять попыток TCP connect, медиана успешных измерений.
- TCP-пробы привязываются к физической Android Network, а не случайно проходят через уже активный VPN.
- Устаревшие результаты проверок не перезаписывают более новые результаты.
- Недоступные и неподдерживаемые для TCP-проверки UDP-профили показываются как `н/д`, а не получают выдуманную задержку.
- Unit-тесты для сортировки, маршрутизации приложений, метаданных подписок, разбора URI и медианы TCP-проб.
- GitHub Actions собирает debug APK, запускает unit-тесты и проверяет APK.

## Важные ограничения

- Значение `TCP … мс` — это время TCP handshake до VLESS endpoint на физической сети. Это **не** ICMP ping и **не** задержка HTTP-запроса через proxy.
- Для Hysteria2 и TUIC TCP-проверка намеренно не используется: это UDP-протоколы, и TCP-порт не подтверждает их работоспособность.
- Изолированный URL-test через отдельный краткоживущий экземпляр sing-box подключён к экрану списка: каждый outbound проверяется HTTP-запросом через собственный proxy, без перезапуска активного VPN. Нулевые промежуточные значения не принимаются за результат; серверы без успешного измерения по тайм-ауту получают `н/д`.
- Страна определяется только по явно указанному имени/тегу профиля; если достоверного обозначения нет, показывается нейтральный значок.
- Совместимость всех вариантов транспорта и параметров подписок Velvet VPN ещё требует проверки на реальных конфигурациях.
- Переподключение, переход Wi-Fi ↔ мобильная сеть, поведение в фоне, Android 14/15 и фактическая скорость должны быть проверены на физическом устройстве.
- Не публиковать VPN-ссылки, UUID, пароли, Reality-ключи или приватные токены.

## Работы над настоящим URL-test (текущий этап)

- Добавлен `SingBoxUrlTestConfig`: он собирает все профили подписки в одну временную конфигурацию sing-box и добавляет нативную группу `urltest`.
- Для каждого профиля создаётся стабильный непрозрачный tag на основе SHA-256; tag сопоставляется с исходной ссылкой только в памяти приложения.
- URL проверки: `https://www.gstatic.com/generate_204`. Измерение выполняется HTTP-запросом через соответствующий sing-box outbound, а не TCP-соединением к порту сервера.
- Конфигурация предназначена для отдельного краткоживущего измерительного экземпляра и намеренно не содержит TUN inbound: она не должна поднимать второй системный VPN.
- Конфигурация проходит `Libbox.checkConfig` тем же ядром sing-box, которое включено в приложение.
- Реализован отдельный lifecycle измерительного экземпляра `AstraLatencyTestService`: локальный CommandServer/CommandClient, запуск URLTest, сбор обновлений outbound-группы, ограничение времени проверки и гарантированное закрытие временного экземпляра. Результаты передаются в UI по локальному broadcast. Это HTTP URL-test через proxy, не ICMP ping.
