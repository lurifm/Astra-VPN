# Astra VPN

Android VPN client на Kotlin, использующий sing-box / libbox.

## Уже реализовано

- Импорт VLESS, Hysteria2 и TUIC share-ссылок и HTTPS-подписок.
- VPN-туннель на базе Android VpnService и sing-box.
- Отдельный sing-box URL-test: HTTP-запрос выполняется через каждый импортированный proxy-outbound, не перезапуская основной VPN-туннель.
- Для профилей без успешного URL-test результата отображается «н/д»; нулевые промежуточные значения не считаются успешной задержкой.
- Дополнительная TCP-проверка DNS и TCP handshake для VLESS endpoint; итог пяти попыток — медиана успешных измерений.
- Сортировка по измеренной задержке; профили без результата находятся внизу.
- Проверка HTTPS-доступности через активную Android VPN Network.
- Предупреждение, если VPN-интерфейс создан, но интернет через VPN не подтверждён.
- Настройки маршрутизации приложений, избранное, фильтр и поиск серверов.
- Зашифрованное хранение профилей с Android Keystore.
- Экспериментальная автопауза VPN для выбранных банковских приложений с Usage Access; сценарии восстановления требуют проверки на конкретном устройстве.
- CI: unit tests, debug APK build и публикация APK как GitHub Actions artifact.

## Важно о показателе задержки

URL-test — это время HTTP-проверки через соответствующий proxy-outbound до контрольного HTTPS endpoint. Это не ICMP ping. Дополнительный показатель «TCP … мс» относится только к TCP handshake с VLESS endpoint и не является задержкой всего VPN-маршрута. Для Hysteria2/TUIC TCP-показатель не подставляется вместо реальной UDP-проверки.

Скорость соединения не ограничивается приложением искусственным rate limit. Фактическая пропускная способность зависит от сети оператора/Wi-Fi, сервера, маршрута и параметров протокола. Перед выводами о скорости нужны испытания на физическом устройстве.

GitHub Actions workflow: `.github/workflows/android.yml`

После успешной сборки APK доступен в разделе Actions → Android CI → Artifacts → AstraVPN-debug.

## Текущий статус

Проект активно разрабатывается. Debug APK предназначен для тестирования; для распространения потребуется отдельная release-сборка, подпись и проверка на реальном устройстве.

## Первая десятка улучшений Astra

В интерфейсе и базовой логике проекта реализованы следующие элементы:

1. Выбор лучшего измеренного сервера по результатам sing-box URL-test с учётом недавних отказов и стабильности.
2. Импорт поддерживаемых ссылок и HTTPS-подписок из буфера обмена одной кнопкой «Добавить».
3. Плитка Astra VPN в быстрых настройках Android.
4. Автоматическое обновление подписок по заданному интервалу и при открытии приложения (если включено в настройках).
5. Понятные сообщения об ошибках и тайм-аут для зависшего состояния обновления подписки.
6. Тёмная минималистичная цветовая схема.
7. Четырёхконечная звезда как главная кнопка подключения, с разным состоянием и пульсацией при активном соединении.
8. Анимированное созвездие в карточке подключения: звёзды и линии мягко оживают при подключении.
9. Звёздный маркер у каждой орбиты в списке; оттенок показывает качество измеренной задержки, обводка — выбранный/активный сервер.
10. Тематические подписи «Орбиты», «Запуск», «Посадка», «Прыжок» без замены понятных системных статусов.

Пункты 1–7 используют уже существующую функциональность проекта; пункты 8–10 добавлены в рамках космического оформления. Наличие исходного кода не заменяет проверку APK на физическом Android-устройстве.

## Вторая десятка улучшений Astra (11–20)

- **11. Цветовая тема:** глубокий тёмно-синий фон, холодные синие/фиолетовые поверхности и единый светлый акцент; палитра применяется в основном экране и Material-теме.
- **12. Анимация запуска:** при нажатии звезда сжимается и вспыхивает, вокруг неё расходится световое кольцо; сохранена тактильная отдача.
- **13. Первое знакомство:** добавлено трёхэкранное обучение со слоганом «Своя орбита. Своя скорость. Своя защита». Можно пройти, пропустить; повторно автоматически не показывается.
- **14. Иконка:** обновлена на светящуюся четырёхконечную звезду на тёмно-космическом фоне.
- **15. Отклик:** используется haptic feedback главной кнопки и плавная анимация её нажатия/состояния.
- **16. Пресеты маршрутизации:** добавлены быстрые варианты «Весь трафик», «Только мессенджеры», «Только браузеры». Список определяется по пакетам приложений, найденным на устройстве; пользователь подтверждает выбор кнопкой «Сохранить».
- **17. Скорость и IP:** добавлен единый тест внешнего IP и скорости загрузки небольшого тестового файла. При активном VPN запросы идут по текущему маршруту устройства; результат зависит от сети и контрольного узла и не является гарантией максимальной пропускной способности.
- **18. Статистика:** в проекте есть оценка текущей скорости upload/download по событиям sing-box, график, средние/пиковые значения и дневная/недельная сводка трафика. Сводка объёма трафика строится по доступным счётчикам proxy outbound; это не разбивка по отдельным приложениям и не гарантированный полный учёт каждого пакета TUN.
- **19. Резервная копия:** уже доступны зашифрованный паролем экспорт и восстановление профилей/подписок через файл. QR-экспорт полного набора настроек пока не реализован.
- **20. Поделиться сервером:** добавлена отдельная кнопка отправки ссылки выбранного сервера через системное меню Android. QR-представление ссылки пока не реализовано.

Проверка исходного кода подтверждает внесение этих изменений. APK-сборка и проверка анимаций/сетевых тестов на физическом устройстве в рамках этого изменения не подтверждены.

## Улучшения 21–30

- **21. Уведомления подписок:** предупреждения об истечении срока и остатке трафика; уведомления появляются при проверке подписок во время открытия приложения.
- **22. Сетевая безопасность:** диагностический экран показывает VPN-транспорт, DNS и IPv6-маршрут; системный Kill Switch включается пользователем в настройках Android.
- **23. Виджет и ярлыки:** виджет рабочего стола показывает состояние VPN, быстрые ярлыки открывают приложение и запускают подключение.
- **24. Английский язык:** добавлены английские ресурсы для части интерфейса, виджета, ярлыков, уведомлений и диагностики; полная локализация ещё продолжается.
- **25. Проверка сервисов:** HTTPS-проверка доступности YouTube, Telegram и ChatGPT через текущую активную сеть.
- **26. Протокольный fallback:** после нескольких последовательных ошибок проверки туннеля Astra сначала рассматривает серверы с другим поддерживаемым протоколом (VLESS, Hysteria2 или TUIC); если таких профилей нет, использует обычный подбор альтернативного сервера.
- **27. Экономия батареи:** настройка уменьшает частоту обновления сетевого мониторинга и запуска проверки состояния туннеля с 1 до 4 секунд.
- **28. Повторное обучение:** трёхэкранное знакомство можно повторно открыть из настроек.
- **29. Обратная связь и журнал изменений:** добавлен экран «Что нового» и системное меню отправки отзыва, в котором можно выбрать Telegram, если он установлен.
- **30. Пасхалка:** семь быстрых нажатий на надпись ASTRA VPN открывают секретную орбиту.

Функции, зависящие от Android, сети и установленных приложений, требуют проверки на реальном устройстве. Протокольное переключение выполняется только после повторных неудачных проверок и не гарантирует восстановление связи, если все доступные профили недоступны.

## Улучшения 31–35

- **31. Автоматическая диагностика:** отчёт сопоставляет состояние сети, подтверждение интернета Android, VPN-транспорт, DNS и результат проверки туннеля, затем предлагает конкретные шаги. Диагностика не доказывает отсутствие утечек.
- **32. Прогноз трафика:** показывает средний суточный расход по двум–шести завершённым дням из локальной истории. Это ориентир по общему трафику устройства, а не точный прогноз лимита подписки.
- **33. Оценка надёжности:** рассчитывает прозрачный ориентировочный балл по сохранённым событиям подключений и ошибок; рядом указывается уровень уверенности. Это не рейтинг uptime провайдера.
- **34. Интерактивная карта орбит:** серверы показаны как звёзды; касание звезды выбирает соответствующий профиль. Цвет использует последнюю измеренную задержку, серый означает отсутствие данных.
- **35. Captive portal:** Astra распознаёт системный признак Android для сетей, требующих авторизации, и добавляет рекомендацию открыть браузер и завершить вход.

Прогноз и оценка надёжности требуют накопления локальной истории. Карта показывает до 36 профилей за один раз. Физическая проверка интерфейса и поведения captive portal на разных версиях Android ещё необходима.

## Улучшения 36–40

- **36. Семейный доступ по QR:** можно показать QR-код выбранного профиля для сканирования на втором устройстве Astra. QR содержит исходную ссылку доступа и потому является секретом: приложение предупреждает об этом до показа. Это передача одного профиля, не управление семейной группой и не отдельная учётная запись.
- **37. Оптимизация по времени суток:** выбор сервера учитывает измеренную сейчас задержку, недавнюю стабильность и ошибки, а при наличии минимум двух подходящих исторических замеров — типичную задержку в том же трёхчасовом интервале и дне недели. История задержек хранится локально до 21 дня.
- **38. Серия дней под защитой:** считает календарные дни с зарегистрированным успешным подключением и показывает текущую серию и суммарные дни. История ограничена последними 100 событиями и не доказывает непрерывную защиту в течение всего дня.
- **39. Качество серверов:** выбор использует актуальные URL-test измерения задержки, историческую нестабильность и недавние отказы; дополнительно учитывается время суток. Отдельная нагрузка сервера и индивидуальная пропускная способность каждого профиля пока не измеряются, поэтому полноценный рейтинг по скорости/нагрузке ещё не завершён.
- **40. Переключение при падении скорости:** опциональная настройка отслеживает снижение входящего трафика более чем на 50% относительно недавнего уровня в течение 10 секунд и пробует другой уже измеренный сервер. Периоды простоя и устаревшие события игнорируются; для защиты от ложных срабатываний нужен недавний уровень не ниже 1 Мбит/с и продолжающийся трафик. Решение опирается на VPN-scoped proxy-счётчики sing-box, а не на общий системный трафик устройства; точность на реальном устройстве ещё нужно проверить.

Все новые функции требуют успешной CI-сборки и проверки на физическом устройстве. QR нельзя пересылать посторонним: в нём содержатся данные доступа к серверу.


## Улучшения 41–45

- **41. Приоритет протоколов и fallback:** существующая политика при повторных сбоях сначала переставляет выше профили с другим поддерживаемым транспортом (VLESS, Hysteria2, TUIC). Это приоритет альтернативных профилей, а не автоматическое преобразование одного сервера в другой протокол.
- **42. MTU и multiplexing:** в генератор конфигурации добавлены расширенные параметры: MTU ограничивается безопасным диапазоном 1280–9000; multiplex (smux) может быть включён только для VLESS. По умолчанию MTU остаётся 1400, multiplex выключен. Экранных переключателей этих параметров пока нет; требуется проверка конфигурации libbox и измерения на реальных сетях.
- **43. Прямой маршрут для российских сайтов:** добавлена опциональная политика для доменных зон .ru, .рф и .su через outbound direct. По умолчанию выключена, поскольку такой трафик обходит VPN. Пользовательский переключатель в интерфейсе ещё не добавлен.
- **44. DNS cache и обработка DNS:** включён независимый DNS-кэш sing-box; DNS-запросы перехватываются правилом TUN и направляются через настроенный DoH resolver. Это снижает риск обхода DNS-маршрута, но само по себе не является доказательством отсутствия DNS/IPv6-утечек.
- **45. Жизненный цикл фонового VPN-сервиса:** сохранены foreground-режим, сериализация старта/остановки, тайм-аут создания TUN, закрытие ресурсов и защита от гонки позднего callback. Опциональное восстановление после завершения процесса использует зашифрованный последний профиль и START_STICKY, если пользователь включил соответствующую настройку и Android перезапустил сервис. Принудительная остановка приложения пользователем не обходится; автоматический запуск после перезагрузки устройства пока не заявляется.

Пункты 42–43 на этом этапе являются поддержкой на уровне генератора конфигурации, а не готовыми пользовательскими настройками. Перед включением новых сетевых режимов требуется валидация конфигурации bundled libbox и тестирование на Android-устройстве.


## Улучшения 46–47

- **46. Live speed и диагностика:** в монитор добавлена строка оперативной диагностики состояния передачи данных, текущего состояния VPN и входящей/исходящей скорости. Для активного туннеля используются события трафика sing-box по proxy outbound; значение является оценкой по событиям подключений, может отсутствовать при простое или устаревать и не гарантирует учёт абсолютно всего TUN-трафика. Общие системные счётчики Android не подменяют эту VPN-оценку.
- **47. Проверка целевого сохранения скорости:** добавлен расчёт процента сохранённой скорости по двум измерениям: базовая скорость без VPN и скорость с VPN; целевой порог по умолчанию — 80%. Добавлены unit-тесты расчёта и проверки некорректных измерений. Автоматическое достоверное измерение baseline/VPN и достижение 80% не заявляются: для этого нужен контролируемый сетевой тест на одном устройстве, в одной сети, с несколькими повторами.

### Как проверить пункт 47 вручную

1. В одной сети отключить VPN и выполнить несколько измерений скорости на одном и том же тестовом сервисе.
2. Включить VPN, подключиться к выбранному серверу и повторить измерения тем же сервисом.
3. Сравнить медианные значения download: скорость с VPN / скорость без VPN × 100%.
4. Повторить для нескольких протоколов и серверов. Результат зависит от сети, сервера, нагрузки и времени измерения.

### Восстановление VPN после перезапуска Android

- При обычном завершении службы Astra удаляет зашифрованную отметку активного туннеля. При аварийном завершении процесса Android эта отметка остаётся доступной для проверки при системном перезапуске sticky-сервиса.
- После восстановления сервис повторно создаёт TUN и только после подтверждения готовности записывает активный профиль. Экран приложения не считает VPN подключённым только по старому флагу: требуется также активный VPN transport Android и сохранённая идентичность профиля Astra.
- Если Android отозвал системное разрешение VPN, служба немедленно закрывает TUN, очищает отметку активного профиля и сохраняет понятную ошибку. Любой новый `ACTION_START` дополнительно проверяет `VpnService.prepare()` на стороне службы, поэтому устаревший вызов из виджета/плитки не может обойти согласие. Нужно открыть Astra VPN, нажать «Подключить» и повторно подтвердить разрешение; автоматический retry до нового согласия не выполняется.
- Перезагрузка телефона и принудительная остановка приложения не запускают VPN автоматически: отдельный boot-start receiver не включён. Это намеренное ограничение до проверки требований фонового запуска и foreground-service на поддерживаемых версиях Android.
- Восстановление после завершения процесса и поведение после перезагрузки требуют проверки на реальном устройстве; успешная сборка не подтверждает работу этих сценариев.
- При переключении Wi-Fi/мобильной сети Astra сначала использует текущую физическую `activeNetwork` Android, а сохранённую сеть — только как fallback, когда Android уже показывает VPN как активную сеть. Это предотвращает выбор старого, ещё кратковременно VALIDATED Wi-Fi вместо нового cellular default.
