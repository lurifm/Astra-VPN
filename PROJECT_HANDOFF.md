## 2. Как продолжать работу с пользователем

Пользователь просит работать непосредственно в GitHub, а не ограничиваться советами и планами.

Согласованный ритм:
1. Работать самостоятельными этапами примерно по **10 процентных пунктов общей готовности**.
2. Внутри этапа не останавливаться на каждом небольшом действии и не задавать вопросы, если решение можно принять безопасно.
3. Делать содержательные логические изменения, предпочтительно одним атомарным коммитом на набор связанных файлов.
4. После изменений перечитывать файлы из GitHub и проверять Actions/CI.
5. В конце этапа кратко сообщать: что сделано, коммиты, результат CI, ограничения и честную оценку прогресса.
6. Заканчивать этап фразой **«Продолжить дальше?»**. Пользователь отвечает «Дальше», чтобы начать следующий этап.
7. Не выдавать серию бессмысленных мелких правок за прогресс на 10%. Процент — грубая оценка реализации всего ТЗ, а не число коммитов.
8. Не утверждать, что сборка или APK готовы, пока GitHub Actions не подтвердил успешные тесты, сборку, проверку и загрузку artifact.

GitHub Actions workflow использует concurrency и может отменять предыдущий run после нового push. Поэтому группировать связанные изменения и не создавать частые промежуточные коммиты.

## 3. Продуктовая концепция и обязательные UX-требования

### Визуальная концепция
- Тёмная космическая тема, основанная на макете, который пользователь присылал ранее.
- Центральная яркая звезда — основная кнопка VPN.
- Орбитальные кольца, аккуратное свечение и плавная анимация.
- Не менять общую концепцию без согласования.
- Сохранять минимализм, единые отступы, скругления, типографику и набор outline-иконок.
- Логотип ASTRA VPN и заголовки не должны обрезаться или переноситься по буквам; адаптировать интерфейс к маленьким экранам.

### Цвета и состояние соединения
- Зелёный: хорошее состояние/низкая задержка.
- Жёлтый: повышенная задержка или неполная проверка.
- Красный: только подтверждённая недоступность или отсутствие VPN-туннеля.
- Порог задержки: зелёный до 100 мс включительно, выше — жёлтый.
- Чёткие состояния главной кнопки: «Подключиться», «Подключаемся…», «Отключить», «Отключаем…».
- Не путать состояние VPN-туннеля с результатом ping или проверкой интернета. Не показывать противоречивые статусы защиты.

### Скорость и отзывчивость
- Интерфейс должен мгновенно визуально реагировать на нажатия.
- Сетевые операции выполняются асинхронно и не блокируют UI.
- Переходы экранов не должны зависать.
- Показывать численную задержку в миллисекундах.
- Если достоверное измерение не получено — показывать «Нет данных»/«н/д», а не объявлять сервер неработающим.
- Не полагаться только на ICMP ping: использовать подходящий TCP/TLS/HTTP или sing-box URL-test.
- Проверка списка серверов должна иметь жёсткий предел 10 секунд, возможность отмены и повторного запуска; один зависший сервер не должен мешать остальным.

### Структура приложения
- Главная: подключение и статистика, без перегруженного списка серверов.
- Отдельный экран серверов: полный список, сортировка по задержке, поиск, фильтры, ручной выбор, авто-выбор лучшего, обновление списка и отдельная кнопка Ping.
- Настройки: параметры и управление.
- Инструменты сгруппировать по категориям, например «Сеть и диагностика» и «Приложение и информация».
- Поддержка — отдельный понятный раздел.
- Убрать декоративные элементы, которые выглядят как реальные данные, если за ними нет настоящих измерений.

## 5. Реализованные инженерные области и важные ограничения

Ниже перечислены направления, которые уже присутствуют в проекте по предыдущему анализу кода/README. Перед дальнейшей модификацией перечитывать актуальные реализации.

### Серверы и измерение задержки
- Отдельный `AstraLatencyTestService` использует sing-box URLTest engine.
- Общий таймаут batch-проверки — 10 секунд.
- Результаты отдельных узлов публикуются по мере завершения; сохраняются частичные результаты.
- Проверка может отменяться через ACTION_STOP.
- Session ID защищает Activity от поздних результатов отменённой/заменённой проверки.
- Запуск libbox/CommandServer/CommandClient перенесён в worker-поток.
- Список результатов и состояние сессии сохраняются через SharedPreferences для восстановления после пересоздания Activity.
- `SingBoxUrlTestConfig.kt` использует HTTPS URL-test на gstatic generate_204; route final direct; присутствует direct outbound.
- Важно: общий 10-секундный batch timeout не равнозначен независимому индивидуальному таймауту каждого сервера. Это потенциальное направление улучшения.
- Неудачный URL-test не должен интерпретироваться как доказательство, что сервер не работает.

### Выбор и история серверов
- `ServerLatencySort.kt`: в ping-сортировке используются только положительные значения; null/0/отрицательные значения отправляются в конец.
- `BestServerSelector.kt`: фильтрация некорректных задержек, штрафы и защита от переполнения.
- `LatencyHistoryStore.kt`: локальная история успешных измерений, SHA-256 ключ профиля вместо хранения URI в ключе, срок истории 21 день, максимум 12 измерений, минимальный интервал записи 60 секунд.
- `TimeOfDayServerOptimizer.kt`: учитывает день недели и трёхчасовой интервал; текущая задержка имеет вес 70%, историческая медиана — 30%; для истории нужно минимум два независимых исторических измерения; свежее текущее измерение исключается из исторической базы (минимальный возраст 60 секунд).
- `LatencyStabilityScorer.kt` и штрафы недавних ошибок применяются при выборе.
- Историческая оценка — вспомогательная эвристика, не измерение загрузки сервера или гарантии качества провайдера.

### Доступность сервисов
- `ServiceReachabilityChecker.kt` выполняет параллельную HTTPS-проверку популярных сервисов.
- HTTP-ответ, включая 403/503, означает, что хост достигнут (`reachable`), но не обязательно что сам сервис доступен (`serviceAvailable`).
- Используется общий таймаут около 9 секунд для группы проверок.
- HTTP-диагностика и тесты на различие reachable/serviceAvailable изменены в недавних коммитах.

### VPN и интерфейс
- Главная кнопка показывает понятные состояния подключения/отключения.
- При отключении UI немедленно показывает «Отключаем…», блокирует повторное действие до ответа сервиса; при ошибке состояние UI восстанавливается.
- Восстановление состояния VPN сверяет сохранённое состояние с фактическим Android VPN transport.
- Проверки результатов сессий защищены от поздних broadcast.
- UI-работа по ping coalesce-ится, чтобы не перестраивать весь список после каждого отдельного результата.

### Подписки, профили, конфигурации
- `SubscriptionParser.kt`: поддержка VLESS, Hysteria2/HY2, TUIC; HTTPS загрузка, HTTPS redirects, ограничение размера 2 MB, проверка host/port, валидация через SingBoxConfigBuilder.
- `SubscriptionRefreshCoordinator` сериализует транзакцию загрузки/парсинга/сохранения.
- `ProfileStore.kt`: профили и URL подписок шифруются AES-GCM с Android Keystore; замена подписки атомарная.
- В проекте есть экспорт/восстановление зашифрованной паролем резервной копии.
- В проекте есть функции мониторинга, статистики трафика, диагностики, уведомлений подписок, виджета/ярлыков, карты серверов, captive portal hints и других расширений; проверять README и исходный код по конкретной задаче.

### Известные незавершённые/ограниченные области (по README и прежнему аудиту)
- Проверка на физическом Android-устройстве остаётся обязательной.
- Нет достоверной независимой пропускной способности каждого VPN-сервера и оценки его фактической загрузки.
- Счётчики скорости Android отражают общий трафик устройства, не чистую скорость VPN-туннеля/конкретного сервера.
- Полный QR-экспорт всех настроек не реализован; QR профиля содержит секретную ссылку доступа.
- Некоторые расширенные параметры генератора конфигурации не имеют пользовательских переключателей.
- Автоматическое восстановление после принудительного завершения процесса/перезагрузки устройства не подтверждено и ранее отмечалось как не реализованное.
- Некоторые функции требуют проверки на реальном устройстве и зависят от Android, сети или внешних приложений.
- Не заявлять, что Kill Switch, DNS/IPv6 защита или диагностика доказывают отсутствие утечек.

Для получения актуального APK:
1. Проверить последнюю сборку в GitHub Actions.
2. Убедиться, что unit tests, build, APK verification и upload завершились success.
3. Открыть artifact `AstraVPN-debug` у успешного run и скачать ZIP.
4. Не путать artifact debug APK с подписанным production APK.
